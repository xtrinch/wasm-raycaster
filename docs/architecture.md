## 2. Units and conventions

- **World units.** One grid cell is 1 by 1. Ground is z = 0, and wall tops, ceilings and
  roofs are z = 1. Player `x`, `y` and `z` (feet) and all movement distances use world units.
- **Eye height** is `z + 0.5`. `move_vertical` and the renderers all assume this.
- **Cells** are `(floor(x), floor(y))`, typed `Cell = (i32, i32)`. Cells can be negative or
  lie outside the grid. Grid reads outside the grid return 0, which means empty with no floor.
- **Segments and slots.** A segment is a wall, door or window placement: a straight piece
  with a position, direction, length and thickness (`SegmentKind`, `segment()` in
  `levelBuilder.ts`). A pillar is a square wall segment. A segment that crosses several
  cells is split into one piece per cell, and each cell stores up to three pieces in the
  three slots of its `u64`.
- **Grid precision.** Wall, door and window geometry is stored in tenths of a cell. `World`
  rejects any position, length or thickness that is not a multiple of 0.1.
- **Directions.** An `east` segment runs along y and a `north` segment runs along x. The
  player spawns at (4, 4) facing north, which is −y (`gameLoop.ts`).
- **Camera** uses the classic DDA raycaster vectors: `dir` is the view direction, `plane` is
  the camera plane, and `plane_y_initial` is the plane's length at spawn. Depths are
  normalized by it.
- **Pitch** is an integer pixel offset of the horizon (`middle_view_y = height/2 + pitch`),
  which is y-shearing, not a real camera rotation. It is clamped to ±200 and drifts back to 0
  at 100 px/s (`player.ts`).
- **Depth** in every buffer is perpendicular distance along the view direction, not
  Euclidean distance. See [section 7](#7-depth-and-compositing).
- **One story only.** The floor pass renders exactly two planes, z = 0 and z = 1. There is no
  wall height in the grid.

## 3. Startup and the frame loop

**Startup** (`state/gameContext.tsx`, `GameStore.initialize`):

1. Load the WASM module. If `wasm-feature-detect` reports thread support, call
   `initThreadPool(navigator.hardwareConcurrency)` to start the Rayon workers.
2. `new GameLoop()` creates:
   - a `GridMap`, which loads the texture bitmaps and calls `buildLevel()` to build the
     `WasmWorld`;
   - `Controls`;
   - a `Camera`, which sizes the canvas to the window rounded up to a multiple of 4,
     allocates persistent WASM buffers and uploads textures asynchronously;
   - the `Player`.
3. `buildLevel()` (`level.ts`) parses every OBJ at startup, uploads each mesh once with
   `addMesh` and adds every placement through `compileLevel` → `WasmWorld.add`.

**Frame** (`GameLoop.frame` → `loop`):

```
requestAnimationFrame
  └─ if more than 10 ms since the last update:      (caps updates at about 100 Hz)
       player.update(controls, map, frameTime)      input → Rust walk / move_vertical / rotate_view
       camera.render(player)                        Rust render() into the shared pixel buffer
         └─ drawWeapon                              2D canvas drawImage
       camera.drawCanvas()                          copy buffer → ImageData → putImageData
```

- `camera.render` returns early until at least 20 texture entries are uploaded (12 types with
  one image each, plus 8 angles for `LADY`).
- The FPS readout averages the last 10 `requestAnimationFrame` intervals, including frames
  skipped by the 10 ms gate, so it is only approximate.
- Window resizes are not handled. The canvas and buffers keep their startup size.

## 4. The world and the grid

`World` (`src/world.rs`) is the only runtime source of level geometry. `WasmWorld` in
`helpers.rs` wraps it for JavaScript.

**Placements** (`world_helpers.rs`, mirrored in `levelBuilder.ts`):

| Placement | Stored as | Removable or movable |
|---|---|---|
| `area` | floor, ceiling and road flags on whole cells; later areas overwrite earlier ones | neither (`add` returns id 0) |
| `segment` (wall, door, window; `pillar` is a square wall) | split into per-cell `Piece`s, packed into grid slots | remove only |
| `sprite` | `Sprite` in `sprites[cell]` | remove and move |
| `model` | baked world-space triangles in `items[id]`, id listed in `models[cell]` for every footprint cell, plus a `CollisionBox` if `solid` | remove and move |

**Packing.** Each cell is one `u64`: flags in bits 0–11 and up to three segment slots of
four 4-bit fields each. The full layout is in the `gridMap.ts` comment.

- `encode_any_order` tries every slot order, because only slots 0 and 1 can be windows, and
  slots 1 and 2 share one door bit.
- `add_segment` checks every cell a segment touches before changing any of them, so a
  rejected segment changes nothing.
- A cell holds at most three segments.

**Edits** re-encode only the touched cells. `bake_model` runs again on every model `move`.

**Legacy value.** A cell whose value is exactly `1` is treated as one full-cell wall
(`wall_slots`, and `value == 1` in `raycast_column`). `World` never produces this value,
because any cell with segments also has its count bits set.

**The grid size is fixed** at construction: `new WasmWorld(13)` in `level.ts`. Sprites can
stand outside it (several trees do), and rays find them there. See
[section 6](#6-visibility-what-is-already-culled).

## 5. Rendering pipeline

`render` in `src/lib.rs` is the single per-frame entry point. It receives raw pointers to
three persistent buffers owned by `Camera`:

- the RGBA pixel buffer (`pixelsRef`, width × height × 4);
- the per-`column_depth` buffer (width);
- the per-pixel `depth` buffer (width × height).

It runs these passes in order:

| # | Pass | Parallelism | Output |
|---|---|---|---|
| 1 | `draw_background_image_prescaled`: sky | rows | copies the pre-scaled panorama into every pixel |
| 2 | `draw_ceiling_floor_raycast`: ground, ceilings, roofs and wall tops | rows | colour for surface pixels; resets `depth` to ∞ and writes surface depth |
| 3 | `draw_walls_raycast` → `raycast_column`: wall DDA | columns | wall, door and window hits as `Sprite`s, sprites and model ids from reached cells, per-`column_depth` buffer |
| 4 | `draw_meshes`: models | triangles, then 8-row bands | colour and depth for model pixels |
| 5 | `draw_sprites_wasm`: walls, doors, windows, sprites | rows | colour, sorted far to near, tested against `depth` |

### 5.1 Sky

`BackgroundImageWasm.set` pre-scales the panorama once, at startup, to the screen height and
twice its aspect width. Each frame copies a horizontally offset window of it, chosen by the
view angle and shifted by pitch. Every pixel is written. Later passes overwrite most of them.

### 5.2 Floors, ceilings, roofs and wall tops

`draw_ceiling_floor_raycast` processes one screen row at a time.

- It considers the plane at height 1 first, then height 0. A plane is a floor when the eye is
  above it and a ceiling when the eye is below it. The ground has no underside.
- Every pixel on a row has the same forward distance to a given plane, so it walks the plane
  in fixed-point steps and reads the grid cell for every pixel.
- A pixel is drawn only if the plane is nearer than what that pixel's `depth` already holds.

Texture selection, from the `match` in the code:

- **Roof** (height 1, seen from above): the roof texture where the ceiling bit is set, or
  inside a wall footprint. Wall tops reuse the same footprint as wall bottoms (`wall_slots`,
  `inside_wall_footprint`).
- **Ceiling** (height 1, seen from below): the ceiling texture where the ceiling bit is set.
- **Ground**: road where the road bit is set, floor where the floor bit is set, or inside a
  wall footprint.
- **Anything else** stays transparent, so the sky shows through.

Lighting is linear fog by distance (`light_range`, `map_light`).

### 5.3 Wall raycast

`draw_walls_raycast` runs `raycast_column` for every screen column in parallel. Each column
does a grid DDA from the player's own cell, for at most `range` cell steps. `range` is 40
steps, set in `Camera`. It is a step count, not a distance.

- **Cells with segments.** Each slot is intersected as a thin box: its front face, and if
  that misses, the side face across its thickness. The intersection uses `geo` lines and
  `LineInterval::relate`. Doors and windows stretch their texture coordinate over their own
  length.
- **Hits** go into the column's `segment_hits` as one-pixel-wide `Sprite`s, each carrying its
  texture type (wall, door or window), the hit `fract` and the Euclidean distance. A hit is
  pushed when it is nearer than the nearest wall or door found so far in its cell, and
  always when the eye is above wall tops. Windows never become the nearest wall, so every
  window hit is pushed. Slots are tested in slot order, so a farther slot tested first is
  pushed too; the painter's sort draws the nearer one over it.
- **What stops the ray:**
  - A wall or door hit sets `hit` and stops the ray at that cell. When a cell holds several
    slots, the nearest hit sets the column's distance.
  - A window hit never stops the ray (`stop_at_window` is false), so whatever is behind
    glass is also found and drawn.
  - When the eye is above wall tops (`z >= 0.5`, `above_walls`), hits do not stop the ray.
    It keeps stepping to find farther walls visible beyond nearer tops, and every hit along
    the way is emitted.
- **Sprite and model cells.** On every 5th column (`column % 5 == 0`), each cell the ray
  enters is checked with `World::occupied`. Occupied cells go into `occupied_cells`.
- **After all columns:**
  - The cells are deduplicated (a `HashSet`).
  - Sprites are collected from those cells with their Euclidean distances.
  - Model ids are collected, sorted and deduplicated.
  - `column_depth[column]` is set to the column's perpendicular wall distance, or ∞ when above
    walls.
  - Every segment hit is appended to the sprite list.

### 5.4 Models

`draw_meshes` rasterizes only the models whose ids the wall raycast collected from the cells
its rays reached ([5.3](#53-wall-raycast)):

- triangle setup in parallel: camera transform, half-space rejects, back-face cull,
  near-plane clip and projection to screen planes;
- a sort of all triangles nearest first;
- a serial assignment to 8-row bands;
- parallel filling, one band per task, with a per-pixel depth test and write.

[models.md](models.md) documents this pass step by step. Each model triangle is
filled with one solid colour, from its material's `Kd` in the MTL file, and shaded by a
fixed sun. No image is wrapped around a model, unlike walls and floors. The women were
originally textured; before the game runs, posebake picks one colour per triangle from their
texture images and writes it into the MTL. Detail smaller than a triangle is therefore lost.

### 5.5 Walls, doors, windows and sprites

`draw_sprites_wasm` handles everything that is not a surface plane or a mesh.

1. Sort all sprites far to near by Euclidean `distance`. Wall hits are included, which makes
   this a painter's algorithm.
2. Project each one with `translate_coordinate_to_camera`. That returns a perpendicular
   depth, a screen x, a top y and a height.
3. Build `SpritePart`s:
   - **A wall, door or window hit** becomes a 1-pixel-wide part at its column. It is dropped
     if every pixel it covers is already behind `depth`.
   - **A sprite** picks its angle texture (8 angles for `LADY`, otherwise 1). Its left and
     right ends are trimmed while they are behind the `column_depth` buffer. Only the ends are
     trimmed: a sprite partly hidden in the middle relies on the painter's order.
4. Fill the screen in parallel by rows. For every row, loop over **all** parts, skip parts
   that do not cover the row, and for each covered pixel:
   - skip texels with alpha 0;
   - darken by distance;
   - skip the pixel if `part.depth >= depth[pixel]`;
   - blend if alpha < 255, otherwise write.

Walls, doors, windows and sprites **do not write `depth`**. Their order among themselves
comes only from the far-to-near sort. Their order against floors, roofs and models comes from
the depth test.

### 5.6 Present

`Camera.drawCanvas` copies the shared WASM buffer into a plain `ArrayBuffer`-backed
`Uint8ClampedArray`, because `ImageData` cannot wrap shared memory. It then calls
`putImageData`. That is two full-frame copies on the main thread.

## 6. Visibility: what is already culled

| What | Where it is skipped | How |
|---|---|---|
| Walls behind other walls | `raycast_column` | Rays stop at the first wall or door hit, except when the eye is above wall tops |
| Sprites behind walls, behind the camera or outside the horizontal FOV | `draw_walls_raycast` | Only sprites in cells that a (sampled) ray entered are collected |
| **Models** behind walls, behind the camera or outside the horizontal FOV | `draw_walls_raycast` → `render` | Same per-cell mechanism; only collected model ids reach `draw_meshes`, which never sees other models' triangles |
| Model triangles behind the eye or entirely left or right of the view | `draw_meshes` setup | Half-space tests on the camera-space corners |
| Back-facing model triangles | `faces_away_from` | Outward side decided by vertex normals |
| Model triangle parts behind the near plane | `clip_to_near_plane` | Clipped at depth 0.05 |
| Model pixels behind floors, roofs or nearer triangles | `draw_meshes` fill | Per-pixel `depth` test, before any shading |
| Wall stripes fully behind floors, roofs or models | `draw_sprites_wasm` | Whole part dropped before the pixel loop |
| Sprite columns at the ends that are behind walls | `draw_sprites_wasm` | Trimmed against the `column_depth` buffer |
| Sprite pixels behind floors, roofs or models | `draw_sprites_wasm` | Per-pixel `depth` test |
| Floor and ceiling pixels behind a nearer plane | `draw_ceiling_floor_raycast` | Per-pixel `depth` test |

What is **not** culled:

- **Vertical FOV for models.** A model in a reached cell is fully set up even when pitch puts
  it off-screen above or below. This is rare in practice.
- **Model level of detail.** A visible model always costs all of its triangles at any
  distance. The two characters have about 21.7k and 32.2k triangles. The furniture has under
  130 each.
- **The sprite pass's row loop.** It visits every part on every row, roughly one wall part
  per screen column plus the sprites.
- **Sky overdraw.** The whole screen is copied, then mostly overwritten.

Cases the per-cell mechanism can get wrong:

- Cells are sampled on every 5th column only. A small or distant sprite or model whose cells
  are crossed only by the columns in between is missed for that frame.
- A ray stops at a wall or door. A model whose own cell is reached only through a wall is not
  found, even if part of it pokes out. Windows do not stop rays.
- Rays run at most 40 cell steps.

## 7. Depth and compositing

There are two depth structures:

| Buffer | Size | Written by | Read by |
|---|---|---|---|
| `depth` (`depthRef`) | per pixel | floor pass (reset to ∞, then surface depth), mesh pass | mesh pass, sprite pass |
| `column_depth` (`columnDepthRef`) | per column | wall raycast (∞ when above walls) | sprite edge trimming only |

Both buffers hold perpendicular depth on the same scale:
`scale = |plane_x·dir_y − dir_x·plane_y| / plane_y_initial`. That scale is what lets a wall
stripe, a sprite, a floor pixel and a mesh pixel be compared directly. The test
`quad_matches_sprite_projection` enforces it.

Final order within one frame: sky → floors, ceilings and roofs → models → walls, doors,
windows and sprites. Glass blends over whatever is already in the frame, so a model behind
a window shows through it.

## 8. Movement and collision

All rules live in Rust. TypeScript computes the requested distances from speed × frame time
and applies the position Rust returns.

| Input | TypeScript (`player.ts`) | Rust |
|---|---|---|
| Arrows left and right | `rotate_view(frameTime, ±1, ...)` | rotates `dir` and `plane` at 0.8π rad/s |
| Arrows up and down | `walk(±3 * frameTime)` | `walk` → `walk_step` |
| A / S | pitch ±400 px/s, in TypeScript only | — |
| D / F | jump up or down at 2/3 unit/s, unless hovering | `move_vertical` |
| G / H | sets `jetpackActive`, ±1 unit/s; releasing both keeps hovering | `move_vertical` |

**`walk`:**

- It gathers collision boxes from every cell overlapping the step's bounding box widened by
  `PLAYER_RADIUS` (0.2):
  - wall and window slots decoded from the grid, with top 1. Doors are excluded, so they
    are always passable;
  - solid model boxes from `CollisionCells`.
- `step_enters_box` tests the whole step segment against each widened box, so long steps
  cannot tunnel.
- If the full step is blocked, it tries the x-only step, then the y-only step, so the player
  slides along walls.
- Feet at or above a box's top pass over it. A player already inside a box can walk out.

**`move_vertical`:**

- **Support** under the feet: the roof (z = 1) where the ceiling bit is set or inside a wall
  footprint, if the feet are at or above 1. Otherwise the highest solid-model top at or below
  the feet, or the ground.
- **Jump limit**: D jumping is capped at support + 0.5.
- **Ceiling**: under a ceiling or wall top (feet below 1), feet are capped at 0.49.
- **Landing**: moving down onto the support reports `landed`, and TypeScript clears
  `jetpackActive`.
- **Gravity** is 1/6 unit/s and does not apply while hovering.

Sprites never collide. Non-solid models never collide. A solid model collides as its
whole axis-aligned footprint box, up to its top.

## 9. WASM boundary, memory and threads

- **Build.** The crate builds with nightly Rust (`rust-toolchain.toml`) and `build-std`,
  with `+atomics,+bulk-memory,+simd128`, shared imported memory capped at 1 GiB
  (`.cargo/config.toml`), and the `parallel` feature enabling `wasm-bindgen-rayon`.
  - `pnpm run build:wasm` is a profiling build (`--out-name in`).
  - `build:wasm-gh`, used by CI, is a release build (`--out-name index`).
  - The app imports the `wasm/` directory, and the generated `package.json` resolves it.
- **Persistent buffers.** `Camera` allocates the pixel, `column_depth` and `depth` buffers once,
  as `WasmUint8Array` and `WasmFloat32Array`, and passes their `.ptr` into `render` every
  frame. Rust turns the pointers into slices with `from_raw_parts_mut`.
- **Textures** are uploaded once, as RGBA, into `WasmTextureMap`, keyed by
  `(TextureType, angle)`. `WasmTextureMetaMap` holds their sizes. Both are SipHash `HashMap`s
  that are read during rendering.
- **The level** lives entirely in Rust (`WasmWorld`). JavaScript receives only ids, and
  `grid()` returns a copy, which the minimap uses.
- **Threads.** Rayon runs on Web Workers sharing the WASM memory. This requires
  cross-origin isolation (COOP/COEP). The dev server gets it from
  `vite-plugin-cross-origin-isolation`.
- **Unused code.** `#![feature(portable_simd)]` is enabled, but no code uses SIMD types.
  `rustc-hash` and `dashmap` are dependencies but are not used.

## 10. Cost model

This section is based on reading the code. Nothing has been profiled yet. For scale, at 1280 × 720 there are about 920k pixels and 1,280 columns.

| Pass | Scales with | Notes |
|---|---|---|
| Sky | pixels | Full-screen copy, mostly overwritten |
| Floors, ceilings, roofs | pixels × 2 planes | Grid read per pixel; footprint test on wall cells; texture fetch |
| Wall raycast | columns × DDA steps × slots | `geo` segment intersection per slot; `occupied()` SipHash lookups on 1/5 of columns |
| Mesh setup | triangles of visible models | about 54k triangles when both characters are visible; zero when they are not |
| Mesh sort and bands | surviving triangles | `par_sort`, then a serial band assignment |
| Mesh fill | covered pixels | Cheap for distant models |
| Sprite projection | parts (about columns + sprites) | One `HashMap` texture lookup per part |
| Sprite fill | rows × parts (rejects) + covered pixels | Every row checks every part's y range |
| Present | pixels × 2 copies | On the main thread |

Per-frame bookkeeping is negligible next to the per-pixel passes:

- `occupied_cells` vectors, which are empty on most columns;
- the cell `HashSet`, a few hundred entries;
- small `SmallVec` clones;
- 12 texture lookups at the start of `render`.

## 11. Known limitations and quirks

- **Weapon overlay.** `drawWeapon` draws on the 2D canvas inside `camera.render`. Then
  `drawCanvas` calls `putImageData`, which replaces every canvas pixel. In this order, the
  weapon is overwritten every frame. Seen in the code; not checked in a browser.
- **Fixed wall height.** All walls are 1 tall. Doors are wall-like slots that render with the
  door texture and never collide. They do not open.
- **Window texture stretch.** A window's thickness is usually 0. Its texture is stretched
  along its length.
- **Sampled sprite discovery.** Sprite and model discovery samples every 5th column (see
  [section 6](#6-visibility-what-is-already-culled)).
- **Sprites are flat cards.** A sprite has one depth for its whole height, so it
  intersects models and roofs as a card at its centre's distance.
- **Approximate column depth.** `column_depth` uses the DDA cell-boundary distance, not the exact
  slot intersection, so sprite edge trimming is approximate near thin walls.
- **No resize handling** (see [section 3](#3-startup-and-the-frame-loop)).
- **Synchronous parsing.** Model OBJ text is bundled with `?raw` and parsed synchronously at
  startup.
- **Stale README.** `README.md` describes an older state, for example that flight tests live
  only on the prototype branch.

## 12. Tests

Run `cargo test` for these. Test bodies live in `src/tests/` and are included with
`#[path]` from the module under test.

| File | Covers |
|---|---|
| `tests/world.rs` | the level fixture packs the same grid and sprites as the TypeScript builder; rejected segments change nothing; window slot reordering; remove and move for segments, sprites and models; model baking (axes, scale, footprint, top); solid models collide |
| `tests/collision.rs` | wall slots → boxes; doors pass but support roof walking; player radius; sliding; passing over tops; no tunnelling through solids; walking out of a solid; multi-cell solids returned once; standing on solid tops |
| `tests/mesh.rs` | mesh depth matches sprite projection; floors hide meshes; walls, glass and meshes composite by depth; nearer triangle wins regardless of order; near-plane clipping; footprint cell registration; only models in cells the rays reach are found (through the real `draw_walls_raycast`) |

No tests cover the floor pass by plane height, the full `render`, or the TypeScript layer.
`NEXT-STEPS.md` lists the floor tests as later work.
